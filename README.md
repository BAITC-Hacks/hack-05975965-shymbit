# AI Sana Challenge Hub

Backend MVP для проекта МНВО и AI Sana.

## 1. Название проекта

**AI Sana Challenge Hub — от бизнес-задачи к студенческому решению**

## 2. Краткое описание

Бизнес часто описывает задачу слишком коротко, поэтому студентам сложно понять, что именно нужно сделать. AI Sana Challenge Hub помогает превратить черновик бизнес-задачи в понятную карточку проекта.

Сервис рассчитан на:

- бизнес, который хочет получить решение своей задачи;
- студенческие команды, которые ищут реальные проекты;
- МНВО и AI Sana, которым нужен единый каталог образовательных задач.

## 3. Что реализовано

Backend MVP поддерживает:

- создание черновика бизнес-задачи;
- генерацию уточняющих вопросов через AI API;
- сохранение ответов бизнеса;
- формирование структурированной карточки проекта;
- расчёт рейтинга готовности задачи от 0 до 100;
- объяснение, каких данных не хватает для публикации;
- публикацию готовых задач в каталоге;
- фильтрацию задач по статусу, навыкам, технологиям и срокам;
- отправку откликов студенческих команд;
- просмотр откликов;
- изменение статуса отклика на `submitted`, `reviewed`, `accepted` или `rejected`;
- архивирование задач;
- валидацию входных данных и обработку ошибок AI API.

## 4. Как работает решение

Основной пользовательский сценарий:

```text
Бизнес создаёт черновик задачи
        ↓
AI задаёт уточняющие вопросы
        ↓
Бизнес отвечает на вопросы
        ↓
AI формирует карточку проекта
        ↓
Система считает готовность задачи
        ↓
Бизнес подтверждает публикацию
        ↓
Задача появляется в каталоге
        ↓
Студенческая команда отправляет отклик
        ↓
Бизнес меняет статус отклика и выбирает команду
```

Рейтинг готовности учитывает наличие проблемы, цели, ожидаемого результата, данных, ограничений, сроков, критериев успеха и контактной информации. Задача считается готовой к публикации при рейтинге не менее 75 баллов.

## 5. Технологии

- **Язык:** JavaScript;
- **Среда выполнения:** Node.js 20 или новее;
- **Web-фреймворк:** Express 5;
- **Валидация:** Zod;
- **Конфигурация:** dotenv;
- **AI:** OpenAI-compatible Chat Completions API;
- **AI-модель по умолчанию:** `gpt-4o-mini`, настраивается через `AI_MODEL`;
- **HTTP-запросы к AI:** встроенный `fetch` Node.js;
- **Хранилище MVP:** JSON-файл `data/db.json`;
- **Тестирование:** встроенный модуль `node:test`.

AI API подключается через переменные окружения `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL`. Реальный ключ не хранится в репозитории.

## 6. Архитектура проекта

```text
src/server.js
    ↓ запуск приложения
src/app.js
    ↓ HTTP-маршруты, CORS, валидация ошибок
src/validation.js
    ↓ проверка входных данных
src/services/aiService.js
    ↓ запросы к OpenAI-compatible AI API
src/readiness.js
    ↓ расчёт рейтинга готовности
src/store.js
    ↓ сохранение задач и откликов
data/db.json
```

Основные компоненты:

- `src/server.js` создаёт хранилище, AI-сервис и запускает HTTP-сервер;
- `src/app.js` содержит REST endpoint-ы для задач и откликов;
- `src/services/aiService.js` изолирует интеграцию с AI API;
- `src/readiness.js` считает рейтинг готовности независимо от AI;
- `src/validation.js` проверяет тела запросов;
- `src/store.js` отвечает за чтение и запись данных MVP;
- `test/api.test.js` проверяет основные пользовательские сценарии.

## 7. Установка и запуск

Требуется Node.js 20 или новее.

```powershell
npm install
Copy-Item .env.example .env
```

Откройте `.env` и укажите ключ AI API:

```env
AI_API_KEY=ваш_ключ
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
```

Запуск production-режима:

```powershell
npm start
```

Сервер будет доступен по адресу `http://localhost:3000`.

Запуск в режиме разработки:

```powershell
npm run dev
```

## 8. Как проверить решение

Автоматические тесты запускаются командой:

```powershell
npm test
```

Для ручной проверки жюри может повторить такой сценарий:

1. Отправить `POST /api/tasks` с названием, описанием, организацией и контактным лицом.
2. Вызвать `POST /api/tasks/{id}/clarify` и получить вопросы AI.
3. Отправить ответы через `POST /api/tasks/{id}/answers`.
4. Вызвать `POST /api/tasks/{id}/generate` и проверить карточку и рейтинг готовности.
5. Если статус задачи `ready`, отправить `POST /api/tasks/{id}/publish` с телом `{ "confirm": true }`.
6. Проверить задачу через `GET /api/tasks`.
7. Отправить отклик через `POST /api/tasks/{id}/applications`.
8. Получить отклики через `GET /api/tasks/{id}/applications` и изменить статус отклика через `PATCH /api/applications/{id}`.

Служебная проверка доступности сервера: `GET /health`.

## 9. Данные и интеграции

Используются следующие данные и интеграции:

- данные бизнес-задач, уточняющие вопросы и ответы бизнеса;
- данные карточек проектов;
- данные студенческих команд и их откликов;
- OpenAI-compatible AI API для генерации вопросов и карточек;
- JSON-хранилище `data/db.json`, которое создаётся автоматически при первом запуске.

Внешние базы данных, авторизация пользователей и загрузка файлов в текущей версии не используются.

## 10. Ограничения текущей версии

- реализована только backend-часть;
- отдельные роли бизнеса, студента и администратора пока не разделены авторизацией;
- JSON-файл подходит для MVP и демонстрации, но не рассчитан на высокую нагрузку;
- AI API требует действующий ключ и доступ к выбранной модели;
- нет встроенной панели администратора;
- нет чата между бизнесом и командой;
- нет автоматического подбора команды по навыкам;
- нет deployed-версии в текущем репозитории;
- локализация интерфейса пока не реализована, пользовательские тексты backend находятся на русском языке.

## 11. Deployed-версия

В текущем репозитории deployed-версия отсутствует. Backend запускается локально по адресу `http://localhost:3000`.

## API endpoint-ы

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/tasks` | Создать черновик задачи |
| `GET` | `/api/tasks` | Получить опубликованные задачи |
| `GET` | `/api/tasks?status=draft` | Получить задачи выбранного статуса |
| `GET` | `/api/tasks/:id` | Получить задачу |
| `PATCH` | `/api/tasks/:id` | Изменить черновик |
| `POST` | `/api/tasks/:id/clarify` | Сгенерировать вопросы через AI |
| `POST` | `/api/tasks/:id/answers` | Сохранить ответы бизнеса |
| `POST` | `/api/tasks/:id/generate` | Сформировать карточку и рейтинг |
| `POST` | `/api/tasks/:id/publish` | Опубликовать готовую задачу |
| `POST` | `/api/tasks/:id/archive` | Архивировать задачу |
| `POST` | `/api/tasks/:id/applications` | Отправить отклик команды |
| `GET` | `/api/tasks/:id/applications` | Получить отклики |
| `PATCH` | `/api/applications/:id` | Изменить статус отклика |

По умолчанию `GET /api/tasks` возвращает только задачи со статусом `published`, поэтому черновики не появляются в публичном каталоге. Для фильтрации доступны параметры `status`, `skill`, `technology` и `deadlineBefore`.
