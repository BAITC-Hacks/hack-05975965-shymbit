# AI Sana Challenge Hub

### От короткой идеи бизнеса — к понятному проекту для студенческой команды

Образовательная веб-платформа: AI помогает бизнесу уточнить задачу, а студентам — найти реальный проект, предложить решение и спланировать работу.

**Владелец задачи хакатона:** МНВО — AI Sana.
**Трек:** образование. **Язык интерфейса:** русский. **Формат:** адаптивное веб-приложение.

> Документация относится к коду ветки `frontend`. Ветки `main` и `backend` развиваются отдельно: их несоединённые изменения не считаются автоматически доступными в этой версии.

## 1. Название проекта

**AI Sana Challenge Hub** — единая площадка для образовательных задач от бизнеса и студенческих команд.

Идея проекта: превратить разрозненные короткие запросы организаций в понятные вызовы, над которыми студенты могут работать, применяя знания на практике.

## 2. Краткое описание: проблема и аудитория

Бизнес часто формулирует задачу в нескольких предложениях. Студентам непонятно, какую проблему решать, какие данные доступны, что должно получиться и как заказчик будет оценивать результат. Из-за этого команды тратят время на уточнения или вовсе не берутся за проект.

Решение помогает последовательно дополнить исходный черновик: задать вопросы, структурировать требования, оценить полноту описания и опубликовать карточку в каталоге.

| Для кого | Какую пользу получает |
| --- | --- |
| Компании и организации | Помощь в постановке задачи, понятная карточка и возможность сравнить предложения команд. |
| Студенты и команды | Реальные проекты, ясные ожидания заказчика и возможность получить практический опыт. |
| Организаторы образовательных программ | Общая площадка взаимодействия бизнеса и студентов. |

**AI помогает подготовить информацию, но решение о публикации и выборе команды остаётся за человеком.**

## 3. Что реализовано

### Задачи бизнеса

- Создание и редактирование черновика: название, описание, организация, контактное лицо, ожидаемый результат, доступные данные, ограничения, сроки, навыки и технологии.
- Генерация уточняющих вопросов через AI API и сохранение ответов заказчика.
- Формирование структурированной карточки: проблема, цель, результат, описание, требования, данные, ограничения и критерии успеха.
- Оценка полноты от 0 до 100 с пояснением недостающих сведений.
- Публикация после подтверждения, архивирование и раздел «Мои задачи».

### Каталог, команды и отклики

- Публичный каталог опубликованных задач с поиском.
- Быстрые направления «AI и данные», «Веб-разработка», «Дизайн» и дополнительные фильтры по навыкам, технологиям и срокам.
- Подробная карточка с разделами описания, оценкой готовности и формой отклика.
- Профили команд: участники, роли, навыки, технологии, портфолио и ссылки GitHub.
- Каталог команд, просмотр профилей, рейтингов и отзывов.
- Отправка предложений решения; рассмотрение, принятие и отклонение откликов.

### AI-помощник команды

- Подготовка плана решения опубликованной задачи с учётом состава и навыков команды.
- Архитектура, этапы, распределение работы, риски, первые задачи и вопросы заказчику.
- Сохранение планов и просмотр истории.
- Проверка структуры ответа и соответствия назначений участникам команды.

### Пользовательский интерфейс

- Русскоязычный адаптивный интерфейс для компьютера и телефона.
- Светлая и тёмная темы с сохранением выбора.
- Golos Text, обновлённый каталог и двухколоночная страница задачи.
- Плавная смена тем, появление блоков и реакции кнопок и карточек; учёт настройки уменьшения движения.
- Валидация форм, уведомления, состояния загрузки, ошибки и повтор загрузки.
- Отдельный демонстрационный режим с тестовыми данными.

### Что означает рейтинг готовности

Оценку рассчитывает сервер по заполненности **восьми элементов**: проблема, цель, ожидаемый результат, доступные данные, ограничения, сроки, критерии успеха и контактное лицо.

~~~text
Полнота = округление(число заполненных элементов / 8 × 100)
~~~

В сервере этой ветки порог — **75 из 100**. Публикация требует готовой карточки, статуса `ready`, соответствующей оценки и подтверждения пользователя. Это **показатель полноты**, а не гарантия качества задачи, достоверности сведений или реализуемости проекта.

## 4. Как работает решение

1. **Бизнес вводит черновик.** Описывает проблему своими словами и указывает известные условия.
2. **AI задаёт вопросы.** Сервер передаёт описание модели; интерфейс показывает уточнения о целях, данных, ограничениях и результате.
3. **Бизнес отвечает.** Ответы сохраняются и дополняют исходную постановку.
4. **Формируется карточка.** AI структурирует сведения, а сервер рассчитывает полноту и поясняет пробелы.
5. **Бизнес проверяет и публикует.** Без подтверждения черновик не появляется в публичном каталоге.
6. **Команда выбирает проект.** Студенты изучают условия, создают профиль и отправляют предложение решения.
7. **Бизнес рассматривает отклики.** Сравнивает предложения и принимает подходящее.
8. **Команда планирует работу.** AI-помощник предлагает технический план с учётом задачи и участников.

~~~text
Черновик → вопросы AI → ответы → карточка и оценка
    → подтверждение публикации → каталог → отклик → выбор команды
    → AI-план первых шагов
~~~

**Вход:** описание проблемы, ответы заказчика и профиль команды.
**Результат:** опубликованная карточка с понятными условиями, отклики и сохранённый план решения.

## 5. Технологии

| Слой | Технологии и назначение |
| --- | --- |
| Frontend | React, TypeScript, React Router — интерфейс, типизация и маршрутизация. |
| Сборка | Vite, TypeScript Compiler, npm и lock-файлы зависимостей. |
| Визуальный слой | CSS и переменные тем, Lucide React, Golos Text, View Transition API с CSS fallback, Web Animations API, IntersectionObserver. |
| Backend | Node.js, JavaScript ES Modules, Express 5 — HTTP API и бизнес-логика. |
| Валидация | Zod — проверка входных данных и структуры AI-плана. |
| Конфигурация | dotenv и переменные окружения. |
| AI | OpenAI-compatible Chat Completions API; модель по умолчанию — `gpt-4o-mini`. |
| Хранение этой ветки | JSON-файл на диске с очередью записи и заменой через временный файл. |
| Проверки | Node.js Test Runner, интеграционные тесты, ESLint, проверка типов и production-сборка. |

Адрес провайдера и модель задаются через `AI_BASE_URL` и `AI_MODEL`. Совместимый сервис должен поддерживать используемый формат `/chat/completions` и JSON-ответы.

│   ├── src/components/     Карточки, формы, темы, AI-планировщик
│   ├── src/lib/            API-клиент, нормализация, mock, анимации
│   ├── src/types.ts        Типы данных интерфейса
│   ├── public/             Статические ресурсы
│   └── test/               Проверки frontend-клиента и интерфейсной логики
├── backend/
│   ├── src/app.js          HTTP-маршруты и бизнес-правила
│   ├── src/validation.js   Схемы данных
│   ├── src/readiness.js    Расчёт полноты карточки
│   ├── src/services/       Интеграция с AI
│   ├── src/store.js        JSON-хранилище
│   └── src/config.js       Конфигурация сервера
└── scripts/                Совместный запуск и проверки запуска
~~~

Frontend не обращается к AI-провайдеру напрямую. Сервер проверяет запрос, вызывает модель, обрабатывает ответ и сохраняет результат. Нормализаторы приводят серверные данные к типам интерфейса. AI-ключ остаётся на сервере.

| Группа API | Примеры маршрутов |
| --- | --- |
| Задачи | `GET/POST /api/tasks`, `GET/PATCH /api/tasks/:id` |
| Уточнение | `POST /api/tasks/:id/clarify`, `/answers`, `/generate` |
| Публикация | `POST /api/tasks/:id/publish` с `{ "confirm": true }`; `/archive` |
| Отклики | `GET/POST /api/tasks/:id/applications`, `PATCH /api/applications/:id` |
| Команды | `GET/POST /api/teams`, `GET/PATCH /api/teams/:id` |
| Отзывы | `GET/POST /api/teams/:id/reviews` |
| AI-планы | `POST /api/tasks/:taskId/assistant/plan`, `GET /api/tasks/:taskId/assistant/plans?teamId=...`, `GET /api/assistant-plans/:id` |
| Доступность сервера | `GET /health` |

Без фильтра статуса каталог возвращает только опубликованные задачи. `status=all` используется для управления задачами, **но в этой ветке не является механизмом авторизации или изоляции владельцев**.

## 7. Установка и запуск

### Требования

- Git.
- Node.js **22.x не ниже 22.13** или **24.x**, npm.
- Интернет и действующий AI-ключ для реальной генерации.
- Доступ на запись в каталог серверного хранилища.

### Шаг 1. Скачать проект и установить зависимости

~~~bash
git clone --branch frontend https://github.com/BAITC-Hacks/hack-05975965-shymbit.git
cd hack-05975965-shymbit
npm run setup
~~~

Команда установки использует `npm ci` и lock-файлы обеих частей.

### Шаг 2. Создать файлы окружения

Из корня проекта, **PowerShell**:

~~~powershell
if (!(Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
if (!(Test-Path frontend/.env)) { Copy-Item frontend/.env.example frontend/.env }
~~~

Для **Bash**:

~~~bash
test -f backend/.env || cp backend/.env.example backend/.env
test -f frontend/.env || cp frontend/.env.example frontend/.env
~~~

Существующие настройки не перезаписываются. Заполните `backend/.env`:

~~~dotenv
PORT=3000
DB_FILE=./data/db.json
AI_API_KEY=replace_with_your_real_key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
AI_TIMEOUT_MS=30000
~~~

Замените ключ-заглушку реальным. Если организатор выдал другой адрес или модель, используйте его настройки. `DB_FILE` разрешается относительно каталога `backend`. Не коммитьте `.env`.

В `frontend/.env`:

~~~dotenv
VITE_API_URL=http://localhost:3000
VITE_USE_MOCK_API=false
~~~

### Шаг 3. Запустить приложение

~~~bash
npm run dev
~~~

Откройте адрес `Local` из вывода Vite, обычно [http://127.0.0.1:5173](http://127.0.0.1:5173).

Скрипт запускает backend, ждёт его готовности и передаёт frontend правильный адрес API. При занятом серверном порте выбирается свободный. Изменения backend и его `.env` применяются с перезапуском. **Ctrl+C** останавливает обе части.

Для раздельного запуска откройте два терминала из корня:

~~~bash
# Терминал 1
npm run dev:backend
~~~

~~~bash
# Терминал 2
npm run dev:frontend
~~~

При раздельном запуске `VITE_API_URL` должен совпадать с фактическим адресом backend.

### Проверка доступности и сборка

[http://localhost:3000/health](http://localhost:3000/health) проверяет сервер, если используется порт 3000. Успешный ответ не подтверждает настройку AI-ключа.

~~~bash
npm --prefix frontend run build
npm --prefix frontend run preview
~~~

Сборка находится в `frontend/dist`. `preview` предназначен для локальной проверки, не заменяет production-хостинг и не запускает backend. Сервер отдельно запускается через `npm --prefix backend start`.

### Режим демонстрации без AI-ключа

Установите `VITE_USE_MOCK_API=true` в `frontend/.env` и запустите:

~~~bash
npm run dev:frontend
~~~

Появится плашка демонстрационного режима. Используются тестовые задачи, команды и имитация AI; изменения теряются после перезагрузки страницы. **Mock показывает интерфейс, а не работу реальной модели.** Корневая команда `npm run dev` намеренно подключает реальный backend и отключает mock.

## 8. Как проверить решение: сценарий для жюри

Запустите приложение с реальным backend, `VITE_USE_MOCK_API=false` и действующим AI-ключом. Используйте вымышленные и несекретные данные.

### A. От идеи до опубликованной задачи

1. Нажмите **«Создать задачу»**. Пример заполнения:

   | Поле | Значение |
   | --- | --- |
   | Название | AI-помощник для первокурсников |
   | Описание | Студенты долго ищут ответы о расписании, документах и правилах обучения. Нужен помощник по открытой базе знаний университета. |
   | Организация | Демонстрационный университет |
   | Контактное лицо | Координатор учебного проекта |
   | Желаемый результат | Веб-прототип, который отвечает на вопросы и показывает источник. |
   | Доступные данные | Открытые регламенты и обезличенные частые вопросы. |
   | Ограничения | Без персональных данных; ответы только по предоставленным материалам. |
   | Сроки | 6 недель |
   | Навыки | NLP, UX, веб-разработка |
   | Технологии | React, Node.js |

2. Сохраните черновик и дождитесь уточняющих вопросов AI.
3. Ответьте по существу: аудитория — первокурсники; результат — прототип поиска; проверка — 30 тестовых вопросов и обратная связь пилотной группы; если ответа нет, помощник должен сообщать об этом.
4. Нажмите **«Сформировать карточку»**. Проверьте проблему, цель, результат и критерии успеха.
5. Если полнота ниже 75, дополните указанные недостающие сведения и повторите формирование. Точные ответы AI и балл могут различаться.
6. Через **«Управление задачей» → «Опубликовать»** подтвердите публикацию.
7. Откройте каталог, найдите задачу поиском и проверьте фильтры. До публикации черновик не должен появляться в публичном каталоге.

### B. Отклик, выбор команды и AI-план

8. В разделе «Команды» создайте профиль `Sana Demo Team` с frontend- и backend-разработчиком. Укажите навыки; портфолио необязательно.
9. В опубликованной задаче нажмите **«Откликнуться командой»**. Выберите профиль, опишите подход и укажите демонстрационный контакт `team@example.com`.
10. В управлении задачей откройте **«Отклики»**. Найдите предложение, переведите на рассмотрение, затем примите.
11. Перейдите в **«Составить план решения с AI»**, выберите команду и задайте акцент: «Сначала минимальный прототип поиска по открытым документам».
12. Сформируйте план. Проверьте этапы, архитектуру, риски и распределение работы между участниками. Откройте сохранённый план через историю.

**Ожидаемый результат:** задача опубликована, команда отправила предложение, бизнес принял отклик, AI-план создан и сохранён.

Дополнительно проверьте смену тем, мобильную ширину, пустой поиск и архивирование. В этой ветке роли сценария проверяются через соответствующие экраны, а не через защищённые аккаунты.

### Автоматические проверки

Из корня репозитория:

~~~bash
npm run test:startup
npm --prefix backend test
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
~~~

Проверяются запуск, API, публикация и каталог, команды, отклики, AI-планы, frontend-клиент, темы и направления каталога. Автоматические AI-сценарии используют подменённый сервис: они не подтверждают доступность внешнего провайдера или качество реальной модели.

## 9. Данные и интеграции

| Источник | Данные и назначение |
| --- | --- |
| Заказчик | Описание, условия, сроки и ответы на вопросы для подготовки карточки. |
| Команда | Участники, роли, навыки, технологии, проекты и предложение решения. |
| AI API | Уточняющие вопросы, структурированные описания и планы работы. |
| JSON-хранилище | Задачи, команды, отклики, отзывы и планы между запусками сервера. |
| Mock frontend | Демонстрационные данные для показа без backend. |

Государственные реестры, университетские LMS, внешние базы вакансий и GitHub API не подключены. Ссылки GitHub в профилях — пользовательские ссылки, а не автоматическая проверка репозиториев. Golos Text загружается через Google Fonts; предусмотрен системный шрифт.

**Обработка данных:** при реальной генерации соответствующие сведения задачи, ответы или данные команды передаются настроенному внешнему AI-провайдеру. Не загружайте секреты и избыточные персональные данные. Условия обработки определяются выбранным провайдером; приложение не гарантирует отсутствие хранения данных на его стороне.

AI-ключ используется только сервером. Его нельзя помещать в `VITE_*`, исходники интерфейса, скриншоты или публичный Git.

## 10. Ограничения текущей версии

- **MVP, а не готовая защищённая production-платформа.** В данной ветке нет полноценной авторизации и проверки прав владельцев. «Мои задачи» не обеспечивает изоляцию данных разных организаций.
- **Ветки требуют интеграции.** Отдельные обновления `backend` с ролями и импортом документов и `main` с PostgreSQL и размещением не включены в описываемую версию автоматически.
- **JSON рассчитан на небольшой однопроцессный MVP.** Нет распределённого хранения; нужны резервные копии. Не запускайте несколько backend-процессов с одним файлом данных.
- **AI может ошибаться.** Проверяйте карточки и планы. Балл полноты не подтверждает достоверность, качество или достижимость результата.
- **Зависимость от сети, провайдера и бюджета.** Без ключа генерация недоступна; возможны ошибки и таймауты. Встроенного учёта общего денежного бюджета нет.
- **Пока только русский язык.** Казахская и английская локализации не реализованы.
- **Нет полноценного сопровождения после выбора команды:** чата, email-уведомлений, календаря, договоров, оплаты и трекера выполнения работ.
- **Нет проверки организаций и квалификации участников.** Пользователи самостоятельно заполняют профили и предложения.
- **Импорт файлов не подключён в этом frontend.** Основной ввод — текстовые формы.
- **Mock-данные временные.** После обновления страницы изменения пропадают; настоящая модель не вызывается.
- **Публикация не равна независимой модерации.** Пользователь проверяет текст и допустимость раскрытия данных.
