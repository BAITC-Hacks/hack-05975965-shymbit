# Контракт ролей и импорта документов

Это описание реализованного backend. Frontend в этой доработке не изменён.
Старый клиент без авторизации больше не может выполнять приватные действия.

## Вход

- `POST /api/auth/register`: JSON `{ "name": "Айдана", "email": "user@example.com", "password": "длинный пароль", "role": "business" }`.
- Роли регистрации: `business`, `student`. Имя: 2–200 символов; пароль: 12–128 символов. Почта нормализуется в нижний регистр.
- `POST /api/auth/login`: JSON `{ "email": "user@example.com", "password": "длинный пароль" }`.
- Успех регистрации: 201, входа: 200. Ответ: `{ "user": { "id", "name", "email", "role" }, "token", "expiresAt" }` (здесь имена без значений обозначают состав полей).
- Передавать `Authorization: Bearer <token>` во всех приватных запросах. Токен действует 24 часа, после перезапуска сессия сохраняется. В базе хранится только SHA-256 токена; пароль обрабатывается scrypt с индивидуальной солью.
- `GET /api/auth/me` возвращает `{ "user": { "id", "name", "email", "role" } }`.
- `POST /api/auth/logout` отзывает текущий токен, ответ 204 без тела.
- Вход/регистрация: суммарно 20 запросов за 15 минут с одного IP, максимум две параллельные операции хеширования.
- Не передавать роль, userId или ownerId для получения прав. Роль выбирается при регистрации и затем читается только из серверного аккаунта. Изменение роли через API отсутствует.
- Cookies не используются. Для развёртывания нужен HTTPS. Хранение токена в памяти клиента предпочтительнее localStorage. При 401 предложить повторный вход.

## Доступ и изменения старых контрактов

| Действие | Доступ |
| --- | --- |
| `GET /api/tasks`, `GET /api/tasks?status=published` | Всем; только опубликованные задачи |
| `GET /api/tasks?status=all` и другие непубличные статусы | Только бизнес; только собственные задачи |
| `GET /api/tasks?mine=true&status=all` | Кабинет бизнеса |
| `GET /api/tasks/:id` | Опубликованная карточка всем, черновик/архив только владельцу |
| Создание задачи | Бизнес; ownerId назначает сервер |
| PATCH, clarify, answers, generate, publish, archive | Только бизнес-владелец |
| Создание команды | Студент; ownerId назначает сервер |
| PATCH команды | Только студент-владелец |
| `GET /api/teams`, `GET /api/teams/:id`, отзывы | Публичные профили без ownerId; собственный профиль доступен полностью |
| `GET /api/me/teams` | Студент; собственные команды, `{ items, total }` |
| POST отклика | Студент; при teamId команда должна принадлежать ему |
| `GET /api/me/applications` | Студент; собственные отклики, `{ items, total }` |
| GET откликов задачи, PATCH статуса отклика | Только бизнес-владелец задачи |
| POST отзыва | Бизнес-владелец задачи, только после принятого отклика команды |
| Создание и чтение AI-планов | Только студент-владелец команды; чужие планы не доступны бизнесу |

Новые отклики без teamId остаются допустимыми, но имеют владельца-студента.
Студент не может принимать собственный отклик. authorName в запросе отзыва остаётся обязательным ради старой схемы, но сервер заменяет его организацией задачи. Подмена имени не позволяет оставить второй отзыв по той же задаче и команде.

Публичная задача содержит только: id, title, organization, status, skills, technologies, deadline, readinessScore, readinessExplanation, createdAt, updatedAt, publishedAt и card. Необязательные отсутствующие поля могут быть опущены.
В card разрешены title, problem, goal, expectedResult, description, requirements, skills, technologies, availableData, constraints, deadline, successCriteria.
Контактное лицо, ownerId, исходное краткое описание и ответы на уточнения посторонним не возвращаются. Владельцу возвращается полная задача.
Свободный текст карточки не является автоматически обезличенным: перед публикацией бизнес обязан проверить его содержание. Публикация по-прежнему требует `{ "confirm": true }`, статуса ready и готовности не ниже 75.

## Сохранение форм и конкурирующие изменения

Для `PATCH /api/tasks/:id`, `PATCH /api/teams/:id` и `POST /api/tasks/:id/answers` нужен заголовок `If-Match` со значением `ETag` последнего `GET` соответствующего объекта.
Сохраняйте ETag именно версии, на которой открыта форма. Не запрашивайте свежий ETag незаметно перед сохранением устаревшего ввода.

1. Прочитать объект через GET и сохранить заголовок ETag (включая кавычки).
2. Пользователь редактирует форму или применяет выбранные предложения импорта.
3. Отправить обычный JSON-запрос с Authorization и If-Match.
4. При 409 сохранить локальный ввод и предложить сравнение с новой версией. При 428 отсутствует If-Match.

После изменения полей задачи или ответов старая карточка и готовность сбрасываются; нужна повторная генерация. Опубликованные и архивные задачи редактировать нельзя. Проверка снимка внутри очереди хранилища также защищает от запоздавших AI-ответов.

## Импорт

`POST /api/imports/extract`, `multipart/form-data`, Authorization обязателен.

| Поле | Содержание |
| --- | --- |
| file | Ровно один файл |
| targetType | task для бизнеса или team для студента |
| targetId | Необязательный UUID существующего объекта; требуется владение |

Отправлять FormData без ручного Content-Type: браузер должен добавить boundary. Дополнительные поля не разрешены.

Поддерживаются PDF с текстовым слоем (`application/pdf`), DOCX (`application/vnd.openxmlformats-officedocument.wordprocessingml.document`), TXT в UTF-8 (`text/plain`). Проверяются расширение, MIME и структура. XLSX, изображения, OCR, макросы и зашифрованные файлы не поддерживаются.

Пример ответа 200:

```json
{
  "importId": "7e9184b6-8b4b-4b66-9e75-d61e409d9917",
  "targetType": "task",
  "suggestions": [{
    "field": "shortDescription",
    "value": "Нужен помощник для проверки учебных заданий.",
    "source": {
      "fileName": "brief.txt",
      "page": null,
      "excerpt": "Нужен помощник для проверки учебных заданий."
    },
    "warnings": []
  }],
  "missingFields": ["title", "organization", "contactPerson", "desiredResult", "availableData", "constraints", "deadline", "skills", "technologies"],
  "warnings": []
}
```

importId — идентификатор ответа, не ссылка на сохранённый файл. История документов и результатов импорта не сохраняется. source.page — номер PDF-страницы с 1, для DOCX/TXT null.

Разрешённые поля task:
- title, shortDescription, organization, contactPerson, desiredResult, availableData, constraints, deadline — строки;
- skills, technologies — массивы строк.

Разрешённые поля team:
- name, description — строки;
- skills, technologies, githubUrls — массивы строк;
- members — массив `{ name, role, skills: [] }`;
- projects — массив `{ name, description, url }`.

Типы, длины и URL проверяются существующими схемами создания task/team. Частичный импорт не требует наличия всех обязательных полей формы. missingFields содержит все разрешённые поля без предложения, включая необязательные. Оно не заменяет валидацию сохранения.

Все строковые значения предложения должны встречаться в одной цитате соответствующей страницы, а цитата — в извлечённом тексте. Нормализуются Unicode, регистр и пробелы. AI не разрешено перефразировать сведения. Если предложение не подтверждено, весь ответ отклоняется с 502, ничего не сохраняется. Доказательство наличия текста не подтверждает истинность документа и не гарантирует правильную трактовку контекста: пользователь проверяет предложения.

Инструкции внутри документа передаются как недоверенные данные. Приложение не запускает код, макросы и ссылки; у AI нет инструментов для их выполнения. Предупреждения о противоречиях зависят от модели и не являются гарантированным семантическим анализом.

Frontend должен показать предложения, источник, предупреждения и отсутствующие поля; применять только выбранные пользователем значения. Импорт ничего не создаёт, не изменяет и не публикует. После подтверждения используется обычное сохранение формы. Не заменять заполненные поля автоматически.

До загрузки frontend должен предупредить о передаче извлечённого текста внешнему AI-провайдеру и предложить не загружать секреты/избыточные персональные данные. Backend не гарантирует отсутствие хранения данных провайдером.

## Лимиты, конфигурация и ошибки

Настройки задаются в локальном `backend/.env`; ключ AI_API_KEY остаётся только на сервере. Ключ и сам .env не коммитить.

```dotenv
IMPORT_MAX_BYTES=10485760
IMPORT_MAX_PAGES=50
IMPORT_MAX_CHARS=50000
IMPORT_TIMEOUT_MS=10000
AI_REQUEST_LIMIT=10
AI_CONCURRENCY=2
AI_TIMEOUT_MS=30000
```

По умолчанию: файл до 10 МБ, PDF до 50 страниц, текст до 50 000 символов. Превышение не обрезается молча. DOCX: до 1000 записей и 20 МБ суммарного заявленного распакованного размера, дополнительный контроль степени сжатия и размеров читаемых записей.
Парсер работает в отдельном Worker с ограничением JS-кучи и времени. Загрузка ограничена 30 секундами. Файлы не записываются на диск: после запроса буфер обнуляется, Worker завершается. Это не гарантия криптографического стирания всех строк из памяти. TTL для файлов не нужен, поскольку временные файлы не создаются.
По умолчанию общий лимит уточнения, генерации, планов и импорта — 10 запросов за 15 минут на пользователя, максимум две параллельные операции на процесс. Ошибочные попытки тоже учитываются. Автоматических повторов AI нет. Для импорта слот занят с момента загрузки до проверки ответа AI.

Формат ошибок: `{ "error": "Сообщение на русском", "details": {} }`, details может отсутствовать.

| Код | Значение |
| --- | --- |
| 400 | Неверные поля, JSON или multipart |
| 401 | Нет действующей сессии |
| 403 | Роль или владение не позволяют действие |
| 404 | Объект не существует |
| 408 | Истекло время загрузки (при разрыве соединения возможна сетевая ошибка) |
| 409 | Конфликт версии, статуса, повторный отзыв или аккаунт |
| 413 | Размер файла, число страниц/символов или распаковка превышают лимит |
| 415 | Неподдерживаемое расширение или MIME |
| 422 | Пустой, повреждённый, зашифрованный документ, скан без OCR |
| 428 | Нет If-Match |
| 429 | Лимит частоты или параллельности |
| 502 | Некорректный/неподтверждённый ответ AI |
| 503 | AI не настроен или недоступен |
| 504 | Таймаут парсинга или AI |

## Старые данные и миграция владельцев

При запуске добавляются users, sessions и ownershipMigrations; существующие коллекции и объекты не удаляются. Старые опубликованные карточки остаются публичными без приватных полей. Старые черновики, записи откликов и планы недоступны для приватного управления, пока оператор явно не назначит владельцев соответствующим объектам.

1. Остановить все процессы backend, использующие эту JSON-базу.
2. Сделать резервную копию базы. Проверить личность владельца вне приложения и создать нужный аккаунт.
3. Из backend выполнить одну команду на каждый подтверждённый объект:

```powershell
node scripts/assign-owner.js tasks ID_ЗАДАЧИ ID_БИЗНЕСА --server-stopped
node scripts/assign-owner.js teams ID_КОМАНДЫ ID_СТУДЕНТА --server-stopped
node scripts/assign-owner.js applications ID_ОТКЛИКА ID_СТУДЕНТА --server-stopped
```

Флаг подтверждает, что оператор остановил сервер; команда не проверяет процессы ОС автоматически. Переназначение уже принадлежащего объекта запрещено; изменение журналируется. Планы становятся доступны владельцу связанной команды. Публичного endpoint присвоения старых записей нет.

## Проверки и ограничения

Из backend: `npm ci`, `npm test`, `npm start`. Нужен Node.js 22.13+ или 24+ с учётом требований PDF.js. В разработке доступны прежние скрипты запуска.

JSON-хранилище и лимитеры рассчитаны на один процесс; нельзя запускать несколько серверов с одной базой. Worker ограничивает JS-кучу, но не является полноценной ОС-песочницей и не задаёт жёсткий предел всей памяти процесса. Для публичного продакшена нужны дополнительная изоляция обработки файлов, мониторинг, резервные копии, HTTPS, согласованная настройка reverse proxy, внешняя база и распределённые лимитеры.

Нет подтверждения email/организации, восстановления пароля, приглашений соуправляющих команды и отзыва всех сессий через UI. Владелец команды пока один, members описывает участников, но не даёт им автоматически права аккаунтов. Регистрация роли business сама по себе не доказывает принадлежность к организации. DOCX читает основной текст документа, не изображения, примечания, сноски и колонтитулы.

Тесты используют синтетические документы и подменённый AI; реальная семантическая точность модели и интеграция с новым frontend требуют отдельной проверки. Проверка npm audit не является аудитом безопасности всей системы.

Использованы документированные API: [Multer](https://github.com/expressjs/multer), [PDF.js для Node.js](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs), [yauzl](https://github.com/thejoshwolfe/yauzl).
